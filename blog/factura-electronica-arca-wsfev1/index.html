Factura electrónica ARCA (WSFEv1): qué necesitás para emitir

Si facturás en Argentina, la factura electrónica no es opcional: es el estándar para casi todas las actividades. La buena noticia es que el camino es claro una vez que sabés qué piezas necesitás. Esta guía resume lo que hace falta para empezar a emitir, ya sea desde el portal o integrándolo a tu sistema de gestión.

Los dos caminos para emitir

Comprobantes en línea. El portal web de ARCA donde cargás cada comprobante a mano. Es gratis, no necesita certificado y sirve si emitís pocas facturas por mes.

Web Service (WSFEv1). Tu sistema —un ERP o software de gestión— se conecta directo a ARCA y emite de forma automática. Requiere un certificado digital, pero es lo que necesitás si facturás volumen o querés que todo quede integrado con ventas, stock y contabilidad.

Qué necesitás: el checklist

  • CUIT y alta fiscal — estar inscripto como Responsable Inscripto o Monotributo.
  • Clave fiscal con nivel de seguridad 3 — es el nivel que habilita a operar estos servicios.
  • Punto de venta dado de alta en ARCA. Importante: si vas por web service, tenés que crear un punto de venta del tipo "Web Services", distinto del de "Comprobantes en línea".
  • El tipo de comprobante que te corresponde — un Responsable Inscripto emite A (a otros responsables inscriptos) y B (a consumidor final o monotributo); un Monotributo emite C.
  • (Solo para web service) Certificado digital — generás una clave privada y un pedido de certificado (CSR) que subís a ARCA para obtener tu certificado (.crt). Ese certificado es lo que autentica a tu sistema ante ARCA.

Cómo funciona la emisión por web service

Cuando emitís con WSFEv1, el flujo es así:

  1. Tu sistema se autentica con WSAA (el servicio de autenticación de ARCA) usando el certificado, y obtiene un ticket de acceso temporal.
  2. Con ese ticket, llama a WSFEv1 (método FECAESolicitar) pidiendo autorización del comprobante.
  3. ARCA responde con el CAE (Código de Autorización Electrónico) y su fecha de vencimiento.
  4. El comprobante final debe incluir el CAE, su fecha de vencimiento y un código QR.

Todo esto ocurre en segundos y queda transparente para quien factura: cargás la venta y el sistema hace el resto.

Fricciones comunes (y cómo evitarlas)

  • Certificado vencido o mal asociado al servicio → la emisión falla. Conviene renovarlo antes de que caduque.
  • Punto de venta equivocado — usar el de "Comprobantes en línea" para web service es un clásico error.
  • Saltos en la numeración — ARCA exige que los comprobantes sean correlativos por punto de venta.
  • Homologación vs producción — ARCA tiene un entorno de prueba (homologación) para validar todo antes de emitir en serio.

Hacerlo desde tu ERP

Toda esta plomería —generar la clave y el CSR, asociar el certificado, autenticarse con WSAA, pedir el CAE y armar el PDF con QR— es justo lo que un buen sistema de gestión resuelve por vos.
